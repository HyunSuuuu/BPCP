[앙팡 택배 물류센터] 물류센터 직무 검토 및 개발 작업 계획 (초안)

참고 자료
- 쿠팡 물류센터 직무 정리 (2026-10-11)
- 앙팡 택배 물류센터 게임 기획 정리 (2026-10-11)
- 기획 변경에 따른 개발 필요 시스템 (APcenter_DevSystems.txt)
- 버거플리즈(BP) 모작 구현 결과 (재사용 가능 기능 기준)

작성 가정 (확인 필요)
- 게임 범위: 허브(HUB) 공정 중심. 기획서의 게임 흐름(입고 → 분류 → 운반 → 적재 → 출고)이 허브 상하차 흐름과 일치하기 때문.
  FC 공정(진열, 피킹, 패킹)은 확장 단계에서 검토.
- 작업 인원: 개발 1명
- 일정 단위: 프로토타입은 일 단위(10일 = 2주, 기획서 목표 기준), 이후 확장은 주 단위
- BP에서 구현한 기능(이동, 운반, 해금, 업그레이드, 알바 AI 등)은 재사용하여 일정 산정


============================================================
1. 직무 → 게임 반영 검토
============================================================

1-1. 핵심 작업으로 반영 (프로토타입)

- 하차 (입고 IB, 허브 HUB)
  → 입고 트럭에서 택배 내리기 작업

- 입고 분류, 허브 분류, 출고 분류 (Sorting)
  → 목적지(지역)별 택배 분류 작업. 세 분류를 게임에서는 "목적지별 분류" 하나로 통합

- 이동, 피딩
  → 분류 구역에서 적재 구역으로 택배 운반 (플레이어, 알바)

- 상차, 적재 (허브 HUB)
  → 배송 차량에 택배 싣기, 차량 출발 시 정산

1-2. 확장 단계에서 반영

- 컨베이어, 소터 (자동화 설비)
  → 자동 운반, 자동 분류 설비. 피딩은 컨베이어 투입 작업으로 연결

- 설비 보전 (예방정비, 고장 수리)
  → 설비 고장 이벤트와 정비 작업. 설비 유지비의 근거

- 지게차
  → 팔레트 단위 대량 운반 장비 (카트 상위 장비) 또는 면허가 필요한 특수 알바(상위 등급)

- 반품 업무
  → 반품 택배 처리 작업 (알바 오분류와 연결: 잘못 분류된 택배가 반품으로 돌아옴)

- ICQA (품질관리, Process Audit)
  → 오분류 감지와 처리 정확도 지표. 평판 수치에 반영

- 현장 관리자 (Area Manager, Team Leader)
  → 관리자: 구역별 생산성 관리, 병목 구역으로 알바 자동 재배치

- 미화 (쓰레기 수거)
  → 작업장 잔해 정리 작업 (BP 쓰레기 정리 재사용)

- 교육 담당
  → 알바 숙련도 성장 연출로 흡수 (별도 직무 없음)

1-3. 이벤트·연출로만 반영 (선택)

- 안전관리 → 안전 점검 이벤트 (위반 시 작업 일시 정지 등)
- 입고 스캔, 검수 → 별도 작업 없이 하차·분류 시 스캔 연출
- 시설관리(FM), 보안·경비 → 배경 NPC 또는 장식

1-4. 제외 또는 보류

- 진열(Stow), 피킹, 패킹 (FC 공정) → 허브 중심 범위에서 보류. 범위 확장 시 재검토
- 재고조사, 재고관리 → 보류
- 신선식품 QC → 제외
- 급식 → 제외 (알바 휴식 시스템을 만들 경우 연출로 검토)


============================================================
2. 작업 계획
============================================================

Phase 0. 준비 (0.5일)

- BP 프로젝트에서 재사용 기능 정리, AP 프로젝트 구조 설정
- 완료 기준: AP 씬에서 플레이어 이동, 운반 스택, 해금 박스 동작


Phase 1. 핵심 루프 프로토타입 (10일)

Day 1. 택배와 목적지
- 택배 데이터(목적지 속성, 목적지별 색), 받는 곳 목적지 필터
- 재사용: 운반 스택, 물건 더미, 자동 줍기·내려놓기

Day 2. 입고 (하차)
- 입고 트럭 도착 → 입고장 정차 → 하차 → 출발
- 상하차 연출 피드백
- 재사용: 차량 이동, 출입문

Day 3. 분류
- 목적지별 분류 구역 (분류 방식 확정 후 구현)
- 재사용: 받는 곳 필터 구조

Day 4. 적재·출고·정산
- 목적지별 배송 차량 대기, 적재, 출발 조건, 처리당 수익 정산
- 재사용: 줄 서기 구조, 카운터 작업 구조

Day 5. 시급 경제
- 알바 시급 주기 차감, 순이익 계산, 적자 상태
- 재화 시스템 음수 허용 수정, 매출·인건비 집계

Day 6. 대시보드와 명령바
- 상단: 보유금, 분당 매출, 분당 인건비, 분당 순이익
- 하단: 고용, 업그레이드, 긴급 요청 버튼
- 재사용: HUD 부품, 업그레이드 카드 패널

Day 7. 알바 작업 전환
- 알바 작업을 하차, 분류, 운반, 적재로 교체
- 작업 공간 배치 (방식 확정 시)
- 재사용: 알바 이동, 작업 예약, 플레이어 가로채기, 우선순위

Day 8. 카트와 첫 업그레이드
- 카트 장비 (적재량, 이동속도 증가), 첫 시설 업그레이드
- 재사용: 업그레이드 시스템, 해금 박스

Day 9. 첫 물량 폭증 이벤트 (앙팡데이)
- 물량 ×2, 수익 ×2, 긴급 알바 투입
- 재사용: 수익 배율, 알림 팝업

Day 10. 밸런스와 검증 빌드
- 초기 밸런스 조정 (수익 > 비용), 버그 수정, 테스트 빌드

Phase 1 완료 기준 (기획서 10장 검증 항목)
- 핵심 조작: 플레이어 이동과 택배 집기·내려놓기, 분류 구역 동작, 적재·출고 연결, 상하차 연출
- 경제 루프: 처리당 수익 정산, 알바 시급 차감, 매출 vs 인건비 표시, 초기 수익 > 비용
- 성장 체감: 첫 시설 업그레이드 효과, 알바 추가 시 병목 해소, 카트 해금 시 운반 효율, 첫 물량 폭증 긴장감


Phase 2. 운영 확장 (약 4주)

1주차. 알바 등급·숙련도
- 등급 4단계, 숙련도 상승, 등급별 시급·처리량
- 긴급 알바 고용·퇴근
- 관리자 (구역 자동 재배치)

2주차. 자동화 설비
- 컨베이어 (피딩 포함), 자동 분류기(소터)
- 설비 유지비, 설비가 맡은 작업의 알바 작업 제외
- 설비 고장과 정비 작업 (설비 보전)

3주차. 물량과 이벤트
- 물량(수요) 시스템, 물량 조절 수단 (영업 업그레이드 등)
- 이벤트: 기상 악화, 긴급 배송, 기업 대량 주문
- 평판 수치

4주차. 품질과 센터 확장
- 오분류와 반품 처리 작업 (ICQA, 반품 반영)
- 잔해 정리 작업 (미화 반영)
- 센터 레벨 Lv.1~6, 단계별 확장 (작은 창고 → 중형 센터 → 메가 허브)
- 지게차 (팔레트 대량 운반)

Phase 2 완료 기준
- 인력 집중형, 완전 자동화형, 하이브리드 운영 판단이 실제 플레이에서 가능
- 센터 Lv.6까지 진행 가능


Phase 3. 범위 확장 (선택, 범위 확인 후 산정)

- FC 공정: 진열(Stow), 피킹(주문 상품 찾기), 패킹
- 안전 점검 이벤트
- 시설관리·보안 배경 연출
- 저장/불러오기, 오프라인 보상


============================================================
3. 일정 요약
============================================================

- Phase 0: 0.5일
- Phase 1: 10일 (2주) → 핵심 루프 프로토타입
- Phase 2: 약 4주 → 운영 확장
- Phase 3: 범위 확인 후 산정


============================================================
4. 확인 필요 사항
============================================================

1. 게임 범위: 허브 중심 / FC 공정(진열, 피킹, 패킹) 포함
2. 하차, 분류를 사람이 하는 작업인지 자동인지 (Day 2, 3 구현 방식 결정)
3. 알바 운영 방식: 모든 일 수행 / 작업 공간 배치 (Day 7 구현 방식 결정)
4. 지게차 반영 방식: 장비 / 특수 알바
5. 반영하지 않는 직무(급식, 시설관리, 보안)의 연출 여부
6. 작업 인원과 일정 (1인 기준 산정, 인원 추가 시 재산정)
