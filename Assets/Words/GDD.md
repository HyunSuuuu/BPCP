# GDD — Burger Idle (가칭)

> 이 문서는 Claude Code가 읽고 게임을 구현하기 위한 기획서(GDD)이다.
> 상태 표기: **[확정]** 사용자가 정함 / **[기본값]** 추천값으로 우선 진행, 변경 가능 / **[제안]** 검토 필요 / **[미정]** 결정 전, 구현하지 말고 질문할 것

---

## 0. Claude Code 작업 지침

1. 한 번에 한 단계(Phase)만 구현하고, 단계 끝에 멈춘 뒤 사용자의 확인을 기다린다. (사용자가 Unity 에디터에서 컴파일·플레이 테스트를 직접 한다.)
2. `.unity` / `.prefab` 파일을 손으로 편집하지 않는다. 게임 오브젝트는 **사용자가 프리팹으로 만들어 관리**한다. **[확정]**
   - 맵 고정 오브젝트(바닥, 해금 박스, 카운터, 기계, 테이블, 쓰레기통, 플레이어): 사용자가 프리팹을 만들어 `MainScene`에 배치한다.
   - 런타임 생성 오브젝트(손님, 알바, 음식, 쓰레기, 돈): 사용자가 프리팹을 만들고, 코드가 오브젝트 풀로 생성한다.
   - Claude Code는 컴포넌트 스크립트를 작성하고, 각 프리팹에 붙일 컴포넌트와 인스펙터 연결 항목을 안내한다.
   - `GameBootstrap`은 오브젝트를 생성하지 않고, 씬 오브젝트 간 참조를 연결한다. (조이스틱 UI는 코드로 생성)
3. **[미정]** 항목은 임의로 정하지 말고 사용자에게 질문한다.
4. 외부 패키지(R3, DOTween)는 사용자가 사전에 설치한다. 설치되어 있지 않으면 코드를 쓰기 전에 알린다.
5. 밸런스 수치는 모두 임시값이다. 코드에 하드코딩하지 말고 ScriptableObject 데이터로 분리한다.

## 4. 아키텍처 규칙

### 4.1 R3 사용 규칙

- 재화, 스탯, 업그레이드 레벨 같은 상태는 `ReactiveProperty<T>`로 보관하고, 외부에는 읽기 전용(`ReadOnlyReactiveProperty<T>`)으로만 노출한다.
- 해금 박스의 투입 금액, 캐릭터의 적재 개수, 테이블의 쓰레기 개수·상태, 돈 더미의 쌓인 금액도 `ReactiveProperty`로 보관해 UI·연출이 구독하도록 한다.
- UI 갱신은 `Update()` 폴링이 아니라 `Subscribe`로 처리한다.
- 모든 `Subscribe`는 `.AddTo(this)` 또는 `CompositeDisposable`로 해제를 보장한다.
- 구버전 UniRx(`using UniRx;`) API를 쓰지 않는다. R3의 `using R3;`와 `Observable<T>` 기준으로 작성한다.

### 4.2 재화 단일 진입점

- 돈과 경험치의 증감은 반드시 `CurrencyManager.Add()` / `CurrencyManager.TrySpend()`를 거친다.
- 음수 방지와 최대값 검증은 이 클래스 안에서만 처리한다.
- 해금 박스의 부분 지불을 위해 `TrySpend`와 별도로, 가진 돈 범위 내에서 최대한 차감하는 `SpendUpTo(int max)`를 둔다. (실제 차감한 금액을 반환) **[기본값]**
- 판매 수익과 팁은 판매·식사 종료 시점에 소지금에 더하지 않는다. 돈 더미에 쌓였다가 플레이어가 수거할 때 `CurrencyManager.Add()`를 호출한다. (6.11)
- **예외:** 배달 성공 보상은 돈 더미를 거치지 않고 성공 시점에 바로 `CurrencyManager.Add()`로 입금한다. (6.14) **[확정]**

### 4.3 데이터 주도

- 업그레이드, 해금 항목, 손님 유형(진상 파라미터 포함), 오브젝트 규격은 ScriptableObject로 정의한다.
- 새 항목을 추가할 때 코드 수정 없이 데이터만 추가하면 되는 구조를 목표로 한다.

### 4.4 오브젝트 풀링

- 음식, 쓰레기, 돈 오브젝트, 손님, 코인 이펙트는 풀링한다.
- 풀에 반납할 때 진행 중인 트윈을 정리하고(`transform.DOKill()`), 위치·크기·상태를 초기화한다.

## 5. DOTween 사용 규칙

- DOTween Pro(유료 버전)가 설치되어 있어 Pro 기능도 사용할 수 있다. `using DG.Tweening;`
- 사용처:
  - 픽업 오브젝트가 스택에 쌓이거나 카운터로 이동할 때 (`DOJump`, `DOMove`)
  - 돈 오브젝트가 돈 더미에 놓이거나 플레이어에게 날아가 수거될 때, 해금 박스로 투입될 때
  - 업그레이드·해금 완료 시 팝 효과 (`DOPunchScale`, `DOScale`)
  - HUD 숫자 카운트업 (`DOTween.To`)
  - UI 패널 등장·퇴장
- 연출 시간은 0.15~0.4초를 기본으로 한다.
- 풀링 오브젝트와 파괴되는 오브젝트에는 `SetLink(gameObject)`를 사용하거나 반납 전에 `DOKill()`을 호출한다.

## 6. 핵심 게임 플레이 루프

### 6.1 루프 요약

```
[시작] 돈 100 → 해금 박스에서 카운터·음식 기계·테이블 해금(각 30)
→ 손님 입장 시작
→ 기계가 음식 생산 → 음식(픽업 오브젝트)을 집어 카운터로 운반
→ 빈 테이블이 있으면 응대 위치의 플레이어/알바가 N초에 1개씩 판매
   → 카운터 옆 돈 더미에 돈이 쌓임 + 경험치
→ 손님이 테이블에서 식사 → 팁(테이블 옆 돈 더미) + 쓰레기 축적
→ 쓰레기를 치워 테이블을 다시 사용 가능하게 함
→ 플레이어가 돈 더미 근처를 지나가며 돈 수거
→ 돈으로 업그레이드·해금 → 가게 확장 → 알바 고용 → 반복

[Zone 2 이후] 버거를 포장 테이블로 운반 → 사람이 서 있으면 버거 4개 → 포장 버거 1개
→ 포장 버거를 드라이브스루 카운터로 운반 → 차량 손님에게 판매 → 드라이브스루 돈 더미
[Zone 3 이후] 배달원이 배달 지점에 도착 → 말풍선으로 품목·수량·남은 시간 표시
→ 제한 시간 안에 필요 수량 제출 → 보상 즉시 입금 / 실패 시 보상 없음
```

### 6.2 게임 시작 흐름 **[확정]**

1. 게임 시작 시 플레이어는 **돈 100**을 가진다.
2. 맵에는 **카운터, 음식(버거) 기계, 테이블**의 해금 박스 3개가 놓여 있다. 각 해금 비용은 **30**이다.
3. 세 가지가 **모두 해금되면 손님이 입장하기 시작**하고, 이때부터 본격적인 게임이 시작된다. (해금 순서는 자유)
4. 세 가지가 모두 해금되기 전에는 손님이 생성되지 않는다.
5. **쓰레기통은 시작 시점부터 설치되어 있다.** 해금이 필요 없다.
6. **초기에는 알바가 없다.** 운반, 판매, 청소 등 모든 일을 플레이어가 직접 한다. 알바는 업그레이드로 고용한다.
7. 3개 해금 후 남는 돈은 10이다. 첫 판매 수익은 돈 더미에서 직접 수거해야 소지금이 된다.

### 6.3 기본 상호작용

- 플레이어는 가상 조이스틱으로 이동한다.
- 모든 상호작용은 **자동**이다. 별도 버튼은 없다. 종류는 아래 네 가지뿐이다.
  - 픽업: 주요 오브젝트 근처에서 자동으로 줍기
  - 내려놓기: 주요 오브젝트 근처에서 자동으로 내려놓기 (카운터 투입, 쓰레기통 버리기)
  - 해금 박스: 0.5초 이상 정지하면 돈 투입 (6.4)
  - 돈 수거: 돈 더미 근처를 지나가면 자동 수거 (6.11, 플레이어 전용)
- 상호작용 범위 판정은 콜라이더·물리 대신 **XZ 평면 거리 검사**로 한다. (`InteractionZone` 컴포넌트) **[기본값]**
- 플레이어와 알바는 같은 상호작용 규칙을 사용한다. 단, 해금 박스 투입과 돈 수거는 플레이어만 한다.

**픽업 규칙**

- **픽업 오브젝트**(음식, 쓰레기 등)를 보유한 주요 오브젝트(기계 출력 지점, 테이블 위 쓰레기 등) 근처에 가면, **0.1초마다 1개씩 자동으로 픽업**한다. **[확정]**
- 한 번에 들 수 있는 개수 N은 **최대적재량** 스탯으로 결정된다. N개를 채우면 더 줍지 않는다. **[확정]**
- 픽업한 오브젝트는 **플레이어 머리 위에 차곡차곡 쌓인다.** **[확정]**
- **음식과 쓰레기는 동시에 들 수 없다.** 음식을 들고 있으면 쓰레기를 줍지 않고, 쓰레기를 들고 있으면 음식을 줍지 않는다. 적재량은 둘이 공유한다. **[확정]**

**내려놓기 규칙**

- 음식은 카운터 투입 지점, 쓰레기는 쓰레기통 근처에서 **0.1초마다 1개씩 자동으로 내려놓는다.** (마지막에 놓은 것부터) **[기본값]**
- 스택이 비면 음식·쓰레기 어느 쪽이든 다시 주울 수 있다.
- **받는 곳마다 받을 수 있는 종류(Kind)가 정해져 있다.** **[확정]** 분류(음식/쓰레기)만으로는 포장 버거가 일반 카운터에 들어가는 문제가 생기기 때문이다.

| 받는 곳 | 받는 종류 |
| --- | --- |
| 일반 카운터 | 버거, 커피 |
| 포장 테이블 | 버거 |
| 드라이브스루 카운터 | 포장 버거 |
| 배달원 | 주문 품목 (기본: 버거) |
| 쓰레기통 | 쓰레기 |

- 스택에 여러 음식 종류가 섞여 있으면, 받는 곳이 받을 수 있는 것 중 **가장 위에 있는 것부터** 내려놓는다. (맨 위가 받을 수 없는 종류여도 그 아래의 받을 수 있는 것을 내려놓음) **[기본값]**

### 6.4 해금 박스 **[확정]**

주요 오브젝트(카운터, 기계, 테이블, 구역 확장물 등)는 처음에는 **해금 박스**로 표시되고, 해금하면 실제 오브젝트로 바뀐다. (쓰레기통은 해금 대상이 아님)

- 해금 박스는 바닥에 놓인 **사각 박스**이며, 비용 텍스트(남은 금액)가 표시된다.
- 플레이어가 박스 안에서 **0.5초 이상 가만히 있으면** 돈을 넣을 수 있다. (조이스틱 입력이 없는 상태 = 정지)
- 박스 안에 있는 동안 소지금이 투입된다. **부분 지불을 허용한다.**
  - 예: 비용 100, 소지금 70 → 박스 안에 서 있으면 70만 투입되고, 박스에는 30이 남는다.
  - 투입 금액은 박스에 보관되고, 이후 다시 돌아와 이어서 채울 수 있다.
- 투입 속도는 일정 속도로 서서히 진행한다. 기본은 약 1.5초에 전액이 들어가는 속도 (비용 ÷ 1.5 / 초, 정수 단위). **[기본값]**
- 박스 밖으로 나가거나 움직이면 투입이 멈춘다. 다시 0.5초 이상 정지해야 재개된다. **[기본값]**
- **비주얼:** 바닥에 눕힌 World Space UI (둥근 사각형 + 흰 테두리 + 비용 숫자·돈 아이콘, 레벨 잠금 시 자물쇠·레벨·별). **[확정]**
- **Fill 연출:** 투입 금액 비율만큼 Filled Image가 화면 아래에서 위로 차오른다. 돈이 코인처럼 날아가 투입되고, 도착할 때마다 박스가 살짝 튄다. **[확정]**
- 투입 금액이 비용에 도달하면 해금된다. 박스가 사라지고 오브젝트가 솟아오르는 Scale 트윈 + 팝 효과를 재생한다. **[제안]**
- 해금 항목에는 선택적으로 **필요 플레이어 레벨**이 있다. 조건 미달이면 박스에 "Lv N 필요"를 표시하고 투입하지 않는다. (6.2의 초기 3개는 레벨 조건 없음) **[기본값]**
- 박스의 비용·결과물·필요 레벨은 `UnlockDefinition` ScriptableObject로 정의한다.

### 6.5 손님 유형과 상태

| 유형 | 설명 | 상태 |
| --- | --- | --- |
| 일반 손님 | 입구에서 줄을 서서 카운터에서 음식을 **1~4개** 받고, 테이블에서 식사한 뒤 팁을 남기고 퇴장 | [확정] |
| VIP 손님 | 일반 손님과 같은 흐름이지만 **다른 색상**이고 버거를 **6~10개** 주문. 좌석 1개 사용(합석 가능), 팁 3배. 등장 확률 10% | 색·수량·좌석 [확정] / 확률·팁 [기본값] |
| 진상 손님 | 줄을 서던 중 멈춰서 길을 막는 손님. 6.8 참고 | [확정] |
| 드라이브스루 손님 (차량) | 차량 출입문으로 들어와 드라이브스루 줄을 서고, 포장 버거를 받으면 바로 퇴장. 테이블·팁·쓰레기 없음. 6.13 참고 | [확정] Zone 2 |
| 배달원 | 사람 출입문으로 들어와 배달 지점에서 주문을 받고 기다림. 6.14 참고 | [확정] Zone 3 (2026-10-13 재추가) |

손님 상태(FSM) **[제안]**

```
Entering(입구에서 줄로 이동) → Queueing(줄 대기)
  → AtCounter(응대 대기, 줄 맨 앞)
       · 빈 테이블 좌석을 예약해야 판매가 진행됨 (예약 실패 시 계속 대기)
  → Served(음식 수령, 판매 완료)
  → MoveToTable(예약한 좌석으로 이동) → Eating(N초) → Leaving(팁 지급, 쓰레기 남김)
Queueing 중 진상 발생 → Blocked → (게이지 완료) → 일반 손님으로 변환 → Queueing
```

- 6.2의 3개 해금이 끝나기 전에는 `CustomerSpawner`가 동작하지 않는다. **[확정]**

### 6.6 손님 줄 (Queue)

- 손님은 입구에서 카운터까지 **일정 간격을 두고 1자로 줄을 선다.** **[확정]**
- 줄 손님에게는 **콜라이더를 사용하지 않는다.** **[확정]** Rigidbody와 물리 충돌 없이 `Transform` 이동으로만 구현한다. 플레이어·알바와 겹쳐도 무방하다.
- 줄은 슬롯(위치 목록) 방식으로 구현한다. `CustomerQueue`가 씬에 배치한 경로 점(카운터 앞 → 줄 끝)을 따라 슬롯 위치를 계산하고, 각 손님은 자기 슬롯으로 이동한다. 앞 슬롯이 비면 경로를 따라 전진한다. **[확정]**
- 손님은 Area의 사람용 입구로 들어와 줄 끝에 합류하고, 퇴장할 때는 Area의 사람용 출구로 나간다. (6.12) **[확정]**
- `CustomerQueue`는 드라이브스루 차량 줄에도 그대로 재사용한다. 차량용 설정(줄 간격·속도)만 다르게 쓴다. (6.13) **[확정]**
- 줄 간격 기본 1.0 유닛, 최대 줄 길이 8명, 입장 간격 3초 (임시값). 줄이 가득 차면 입장하지 않는다. **[기본값]**
- 손님 입장 속도는 해금된 구역·카운터 수에 비례한다. **[제안]**

### 6.7 카운터와 판매

- 카운터는 **손님이 음식을 받는 곳**이다. 플레이어·알바가 투입한 음식이 카운터 재고로 쌓인다. **[확정]**
- **판매는 플레이어와 알바 모두 할 수 있다.** 응대 위치에 서 있고, 카운터에 재고가 있고, 줄 맨 앞 손님이 있고, **빈 테이블 좌석이 예약된 상태**이면 **N초에 1개씩** 판매한다. **[확정]**
- **음식을 받으려면 빈 테이블이 있어야 한다.** **[확정]** 줄 맨 앞 손님은 입장 가능한 테이블(6.9)의 빈 좌석을 먼저 **예약**하고, 예약에 성공해야 판매가 진행된다. 빈 좌석이 없으면 손님은 줄 맨 앞(AtCounter)에서 계속 기다리며, 이때는 판매가 일어나지 않는다.
- 예약된 좌석은 그 손님이 앉을 때까지 다른 손님이 쓸 수 없다. 예약 시점에 해당 테이블의 청소 후 누적 착석 수(6.9)가 증가한다.
- 별도의 대기 위치는 없다. (음식을 받은 손님은 바로 예약한 좌석으로 이동한다)
- **손님은 음식을 여러 개 주문한다.** 일반 손님 1~4개, VIP 손님 6~10개 (무작위). **[확정]** (커피 해금 후 주문 종류는 **[미정]**)
  - 판매는 N초에 1개씩 주문 수량만큼 이어서 진행한다. 판매 1건(음식 1개)마다 돈 더미에 판매가, 경험치를 지급한다. **[기본값]**
  - 재고가 부족하면 있는 만큼만 주고, 손님은 맨 앞에서 나머지를 기다린다. 주문을 모두 받아야 좌석으로 이동한다. **[기본값]**
  - 받은 음식은 손님 머리 위에 쌓인다.
  - 줄 맨 앞 손님 머리 위에 **주문 말풍선**(버거 아이콘 + 받은 수 / 주문 수)을 표시한다. VIP는 말풍선 색을 다르게 한다. **[확정]**
- N(판매 간격)은 **플레이어 0.1초 고정**, **알바 1초 ÷ 알바 행동 속도**(업그레이드로 오름)이다. **[확정]**
- 응대 위치는 카운터 앞 1곳이며 한 번에 1명만 점유한다. 알바가 판매 중일 때 플레이어가 응대 위치에 들어오면 **플레이어가 우선**하고, 알바는 다음 작업을 가져간다. (9.3) **[확정]**
- 판매 진행도 게이지는 표시하지 않는다. (플레이어 판매 간격이 0.1초라 의미 없음. 알바용 게이지는 알바 단계(P9)에서 검토) 판매자가 자리를 비우면 진행도는 유지한 채 멈추고, 손님이 바뀌면 초기화된다. **[확정]**
- 재고가 없거나 판매자가 없으면 손님은 계속 기다린다. (인내심 시간 제한 없음) **[기본값]**
- 판매 완료 시: 재고 차감 → **카운터 옆 돈 더미에 돈 오브젝트 추가**(소지금은 아직 오르지 않음) → 경험치 지급 → 손님은 Served 상태가 되어 예약한 좌석으로 이동한다.

### 6.8 진상 손님

- 줄을 서던 중 **현재 자리에서 멈춰서 길을 막는다.** 진상 손님 뒤의 손님들은 앞으로 나아가지 못하고, 앞쪽 손님들은 정상 진행한다. **[확정]**
- 플레이어 또는 알바가 **근처에 가면 게이지가 차오른다.** 게이지가 가득 차면 진상짓이 해결되고 **일반 손님으로 변환**된다. **[확정]**
- 변환 후 줄은 밀려 있던 만큼 **한꺼번에 앞당겨진다.** (멈춰 있던 동안 생긴 빈 슬롯을 채우도록 뒤 손님들이 전진) **[확정]**
- **해결하면 일정량의 돈을 받는다.** **[확정]** 보상은 카운터 옆 돈 더미에 돈 오브젝트로 추가되고, 플레이어가 수거해야 소지금이 된다. (누가 해결했든 동일) **[기본값]**
- 진상 손님은 **파라미터로 관리**한다. **[확정]** `CustomerConfig`(ScriptableObject)에 아래 값을 둔다.

| 파라미터 | 설명 | 임시값 | 상태 |
| --- | --- | --- | --- |
| spawnChance | 손님 입장 시 진상일 확률 | 0.1 | [기본값] |
| resolveSpeed | 게이지가 차는 속도 (초당 비율) | 0.5 (2초에 가득) | [기본값] |
| rewardMoney | 해결 시 받는 돈 | 15 | [기본값] |
| maxConcurrent | 줄에 동시에 존재할 수 있는 수 | 1 | [기본값] |
| gaugeDecayOnLeave | 범위를 벗어났을 때 게이지 감소 속도 (0이면 유지) | 0.25 / 초 | [기본값] |

- 여러 명이 동시에 근처에 있어도 게이지 속도는 중첩되지 않는다. **[기본값]**
- 게이지는 월드 공간 UI 바로 표시한다. 색은 일반 손님(노랑)과 구분되는 빨강에서 변환 시 노랑으로 바뀐다. **[제안]**
- 방치 시 이탈하는 시간 제한은 두지 않는다. **[기본값]**
- 6.2의 해금이 끝나기 전에는 발생하지 않는다.

### 6.9 테이블과 식사

- 테이블은 카운터에서 음식을 받은 손님이 **식사하는 곳**이다. **[확정]**
- **한 테이블에 손님 2명이 앉을 수 있다.** 손님은 알아서 **합석**한다. (좌석 예약은 6.7. 입장 가능한 테이블 중 가까운 곳 선택) **[확정]**
- **음식은 테이블 가운데 한 곳(공유 음식 더미)에 모인다.** 앉은 손님들은 음식을 **공유해서 함께 먹고, 식사가 끝나면 함께 떠난다.** **[확정]**
- **식사 시간 = 버거 1개당 시간 × 테이블 위 버거 수.** (기본 식사 시간 없음) 식사 중에는 버거 1개당 시간마다 음식 더미에서 1개씩 줄어들어 먹고 있음을 보여 주고, 더미가 비면 식사가 끝난다. 식사 중에 합석한 손님이 오면 그 손님의 버거가 더미에 더해져 식사가 길어진다. 강화할수록 시간이 짧아진다. **[확정]** (개당 1.5초 [기본값])
- 예약만 하고 아직 도착하지 않은 손님은 식사가 끝나도 남아 있고, 도착하면 새 식사를 시작한다. **[기본값]**
- **식사가 끝나면** 테이블 위 음식이 사라지고, **먹은 버거 1개당 쓰레기 1개**가 테이블 가운데(쓰레기 더미)에 쌓인다. 앉아 있던 손님은 **각자 팁을 주고** 함께 퇴장한다. 팁은 테이블 옆의 작은 공간(팁 더미)에 돈 오브젝트로 쌓인다. 플레이어가 그 근처를 지나가면 수거된다. (6.11) **[확정]**
- 플레이어 또는 알바가 **테이블 근처에 가면 쓰레기를 픽업**할 수 있다. (6.3 규칙: 0.1초마다 1개, 음식을 들고 있으면 불가) **[확정]**
- **테이블이 다시 사용 가능해지는 조건:** 착석·예약 중인 손님이 0명이고, 쌓인 쓰레기가 0개일 때. **[확정]** 이 조건을 만족하면 손님이 앉을 수 있다.
- **강제 청소 상태:** 손님이 번갈아 한 명씩 오면 쓰레기가 치워지지 않고 쌓이기만 할 수 있다. 이를 막기 위해 **청소 이후 좌석을 예약·착석한 손님이 누적 2명이 되면 그 테이블은 "강제 청소(MustClean)" 상태**가 되고, 쓰레기를 모두 치울 때까지 새 손님이 예약할 수 없다. **[확정]**

테이블 상태 규칙 **[확정: 구현 구조]**

```
필드: Seats[2](Sit Point), FoodPile(공유 음식), TrashPile(쓰레기), TipPile(팁 더미),
      SeatedSinceClean(청소 후 누적 예약·착석 수), 식사 남은 시간

입장 가능(Available):  SeatedSinceClean < 2 이고 예약·착석 손님이 없는 좌석이 있음
좌석 예약 시: SeatedSinceClean++
              SeatedSinceClean == 2 → 입장 불가(MustClean). 이미 먹고 있는 손님은 계속 식사
착석 시:     손님의 음식을 FoodPile에 추가. 식사 중이 아니면 식사 시작 (식사 중이면 더미가 늘어 자연히 연장)
식사 중:     개당 시간마다 FoodPile에서 1개 제거(작아지며 사라짐), 먹은 수 +1. FoodPile이 비면 식사 종료
식사 종료 시: 먹은 버거 수만큼 TrashPile에 쓰레기, 앉은 손님마다 팁, 앉은 손님 함께 퇴장
쓰레기 픽업 시: TrashPile에서 1개 제거
초기화 조건:  예약·착석 중 0명 && 쓰레기 0개 → SeatedSinceClean = 0, 입장 가능
```

- 예시 1: A(버거 2), B(버거 3)가 함께 앉음 → 1.5×5초 식사 (버거가 1.5초마다 하나씩 줄어듦) → 함께 퇴장 → 쓰레기 5개 → 모두 치우면 사용 가능
- 예시 2: A가 먼저 앉아 식사 후 퇴장(쓰레기 남음) → B가 예약(누적 2명, 입장 불가) → B 식사 후 퇴장 → 쓰레기를 모두 치워야 사용 가능
- 쓰레기를 다 치웠어도 아직 식사 중인 손님이 있으면 초기화되지 않는다.
- 팁 수거 여부는 테이블 초기화 조건과 무관하다. (돈 더미는 테이블 상태와 독립)
- 식사 시간 버거당 1.5초, 팁 3 (VIP 3배) (임시값). 테이블 강화 레벨은 모든 테이블 공통으로 시작한다. **[기본값]** (14장 9번)
- 쓰레기는 테이블 가운데 쓰레기 더미에 격자로 쌓인다. (VIP가 앉으면 쓰레기가 많이 나온다)

### 6.10 쓰레기통

- 쓰레기를 들고 있는 플레이어 또는 알바가 **쓰레기통 근처에 있으면 쓰레기를 자동으로 버린다.** **[확정]**
- **쓰레기통은 시작부터 설치되어 있으며 해금이 필요 없다.** **[확정]**
- **쓰레기를 버리는 것에는 업그레이드도, 보상(돈·경험치)도 없다.** **[확정]** 핵심은 쓰레기를 치워 **테이블을 사용 가능한 상태로 되돌리는 것**이다.
- 쓰레기통에는 용량 제한이 없다. (가득 참 상태 없음) **[기본값]** 버리는 속도는 6.3의 내려놓기 규칙(0.1초에 1개)을 따른다.

### 6.11 돈 획득과 돈 더미 **[확정]**

돈은 **플레이어가 직접 수거해야** 소지금이 된다. 알바는 수거하지 않는다.

**돈이 생기는 곳**

| 발생 | 쌓이는 곳 | 비고 |
| --- | --- | --- |
| 음식 판매 | 카운터 오브젝트 옆의 작은 공간 (카운터 돈 더미) | 판매 1건 = 돈 오브젝트 1개 |
| 진상 손님 해결 보상 | 카운터 돈 더미 | 6.8 [기본값] |
| 식사 종료 후 팁 | 해당 테이블 옆의 작은 공간 (테이블 팁 더미) | 손님 1명 = 돈 오브젝트 1개 |
| 드라이브스루 판매 | 드라이브스루 카운터 옆 돈 더미 | 6.13 [기본값] |
| 배달 성공 보상 | **돈 더미 없음, 즉시 입금** | 6.14, 유일한 예외 [확정] |

**수거 방법**

- 플레이어가 돈 더미 **근처를 지나가기만 하면** 자동으로 수거된다. (정지 불필요, 쓰레기·음식을 들고 있어도 가능)
- 돈 오브젝트가 플레이어에게 날아가며(DOTween) 도착 시 `CurrencyManager.Add()`로 소지금에 더해진다. 수거 간격은 0.05초 / 개 (임시값). 위층(마지막에 놓인 것)부터 수거한다. **[기본값]**
- 돈 오브젝트 1개는 발생 시점의 금액(예: 판매가 10, 팁 3)에 **수익 배율을 곱해 반올림한 금액**을 갖고 있다. 수거 시 그 금액이 더해진다. (8.2)

**돈 오브젝트 규격과 쌓는 방식**

- 크기 비율은 **1 × 2 × 0.2** (가로 × 세로 × 두께)이며, 지폐처럼 납작하게 눕혀 놓는다. 실제 월드 크기는 비율을 유지한 채 배율로 조절한다. (기본 배율 0.25 → 0.25 × 0.5 × 0.05, 격자 한 층의 바닥 면적이 약 1 × 1 유닛이 되도록)
- 한 층은 **가로 4줄 × 세로 2줄 = 8개**의 격자이다. 돈 오브젝트는 이 칸에 **차곡차곡** 채워진다. (세로 방향이 길이 2 쪽)
- 한 층이 다 차면 **그 위로 한 칸(한 층)씩** 쌓아 올린다.
- 쌓인 개수가 많아질 때를 대비해 표시 개수 상한을 둔다. 기본 10층(80개)이며, 상한 이후의 돈은 마지막 오브젝트의 금액에 합산해 개수를 늘리지 않는다. **[기본값]**
- 돈 오브젝트는 풀링한다. 놓일 때 `DOJump`, 수거될 때 `DOMove` + 풀 반납.
- 쌓인 총 금액은 `MoneyPile.TotalAmount` (`ReactiveProperty<int>`)로 보관한다. (알바나 UI가 구독 가능)

### 6.12 Area와 출입문 **[확정: 도입]**

손님·배달원·차량이 각자 입구와 출구를 갖고 있어 스포너마다 따로 지정하면 동선 관리가 흩어진다. 출입문을 **Area**에 모아 한곳에서 관리한다.

- **Area** = 매장 전체 영역. 그 안을 Zone 단위로 확장한다. (10장) 데모는 **Area 1개**만 사용한다. **[확정]**
- Area는 **출입문(Gate)** 목록을 갖는다. 출입문은 용도별로 나눈다. **[기본값]**

| 출입문 | 사용 |
| --- | --- |
| 사람 입구 | 손님, 배달원 입장 |
| 사람 출구 | 손님, 배달원 퇴장 |
| 차량 입구 | 드라이브스루 차량 진입로 |
| 차량 출구 | 드라이브스루 차량 진출로 |

- 출입문은 **바깥 점 → 안쪽 점** 2개로 구성한다. 들어올 때는 바깥에서 생성되어 안쪽 점을 지나 목적지로, 나갈 때는 안쪽 점을 지나 바깥 점에서 사라진다. 벽을 뚫고 걷지 않게 하기 위함이다. **[기본값]**
- 스포너(손님·차량·배달원)는 입구·출구 Transform을 직접 갖지 않고 **Area와 출입문 종류**를 참조한다. **[확정]**
- `CustomerQueue`는 줄 경로만 담당하고, 줄 끝까지의 동선은 출입문에서 시작한다. **[확정]**

### 6.13 드라이브스루와 포장 **[확정]**

일반 카운터와 역할은 같지만, **버거를 포장한 뒤** 드라이브스루 카운터에서 **차량 손님**에게 판매한다.

```
버거 기계 → (운반) → 포장 테이블에 버거 투입
→ 포장 위치에 사람이 서 있고 버거가 4개 이상이면 포장 진행 → 포장 버거 1개가 출력 지점에 쌓임
→ (운반) → 드라이브스루 카운터에 포장 버거 투입 (재고)
→ 응대 위치(창구)에 사람이 서 있고 맨 앞 차량이 대기 중이면 판매 → 드라이브스루 돈 더미 + 경험치
→ 차량은 포장 버거를 받고 차량 출구로 퇴장
```

**포장 테이블**

- 버거만 받는다. (6.3 받는 종류) **[확정]**
- **버거 4개 → 포장 버거 1개.** **[확정]**
- **포장 위치에 플레이어 또는 알바가 서 있어야** 포장이 진행된다. 자리를 비우면 진행도는 유지한 채 멈춘다. **[확정]**
- 포장 간격(포장 1개당 걸리는 시간): 플레이어 0.5초 고정, 알바 2초 ÷ 알바 행동 속도 **[기본값]**
- 버거 투입 칸 상한 8개, 포장 버거 출력 칸 상한 4개. 출력 칸이 가득 차면 포장하지 않는다. **[기본값]**
- 포장 진행도는 짧지 않으므로(0.5초 이상) 월드 게이지로 표시한다. **[기본값]**

**드라이브스루 카운터**

- 포장 버거만 받아 재고로 보관한다. 역할은 일반 카운터와 같다. **[확정]**
- 응대 위치(창구) 1곳. 판매 간격은 일반 카운터와 같다 (플레이어 0.1초, 알바 1초 ÷ 행동 속도). **[기본값]**
- **차량 1대 = 포장 버거 1개.** 판매가·경험치 = 버거 판매가·경험치 × 포장에 든 버거 수(4) × **1.5** (포장 노동 추가금 +50%). 기본값으로 판매가 60, 경험치 30. 수익은 드라이브스루 카운터 옆 돈 더미에 쌓인다. **[확정]** (배율 수치는 추후 조정)
- 드라이브스루 카운터는 일반 카운터와 같은 컴포넌트를 쓰고, 파는 종류만 포장 버거로 지정한다. **[기본값: 구현 구조]**
- 테이블 좌석 조건이 없다. 차량은 받자마자 떠난다. **[확정]**
- 재고 상한은 일반 카운터와 함께 정한다. (14장)

**차량 손님**

- 차량은 손님과 같은 역할이다. 줄을 서서 기다리고, 판매되면 퇴장한다. **[확정]**
- 줄은 `CustomerQueue`를 재사용한다. 차량용 설정: 줄 간격 3.0, 최대 4대, 이동속도 4, 입장 간격 6초. **[기본값]**
- 손님과 차량은 "줄을 서서 이동하는" 공통 동작을 공유하고, 받은 뒤의 행동만 다르다. (손님: 테이블로, 차량: 바로 퇴장) **[기본값: 구현 구조]**
- 진상 차량은 없다. **[기본값]**
- Zone 2가 모두 해금되면 차량이 오기 시작한다. **[기본값]**
- 차량은 전용 입구·출구(차량 출입문)를 따로 쓰고, Zone 2의 도로를 따라 창구 앞을 한 방향으로 지나간다. **[확정]**

### 6.14 배달 **[확정]**

배달원이 정해진 배달 지점으로 찾아와 특별 주문을 하고, 제한 시간 안에 수량을 채우면 보상을 즉시 받는다.

**등장**

- 배달은 **지정한 시설 묶음(UnlockZone)이 모두 해금된 뒤부터** 찾아온다. 기본은 배달 지점이 있는 Zone 3의 시설 완료. **[확정]** (2026-10-13 재추가)
- **배달 지점은 평소에는 아무것도 받지 않고, 배달원이 도착해 주문하는 동안만 받는 곳(임시 판매대)이 된다.** **[확정]**
- 배달원은 Area의 사람 입구로 들어와 **고정된 배달 지점**으로 걸어간다. **[확정]**
- 한 번에 배달원은 1명이다. **[기본값]**
- **배달이 끝난 시점(성공·실패 모두)부터 N초 뒤** 다시 등장한다. N = 30초. **[확정: 규칙 / 기본값: 수치]**

**주문과 말풍선**

- 배달 지점에 도착하면 머리 위에 **말풍선**이 나타난다. 이때부터 제한 시간이 흐른다. **[확정]**
- 말풍선 내용 (레퍼런스 이미지 기준): 제목 "SPECIAL ORDER", 남은 시간(분:초), 품목 아이콘, 제출 수량 / 필요 수량 (예: 3/19). **[확정]**
- 주문 데이터는 `DeliveryConfig`(ScriptableObject)로 관리한다. **[기본값]**

| 파라미터 | 설명 | 임시값 | 상태 |
| --- | --- | --- | --- |
| orderKind | 주문 품목 | 버거 | [확정] |
| quantityMin / Max | 필요 수량 범위 | 5 ~ 10 | [기본값] |
| timeLimit | 제한 시간 | 90초 | [확정] |
| rewardMultiplier | 성공 보상 = 일반 판매가·경험치 × 수량 × 배율 (돈은 수익 배율 적용) | 2 (버거 1개당 20원·경험치 10) | [확정] |
| respawnDelay | 배달 종료 후 재등장까지 | 30초 | [기본값] |
| firstDelay | 배달이 열린 뒤 첫 등장까지 | 5초 | [기본값] |
| urgentTime | 남은 시간이 이 값 이하면 알바가 우선 처리, 말풍선 시간이 빨강 | 20초 | [확정] |

**제출**

- 음식을 들고 **배달원 근처에 가면** 주문 품목을 0.1초마다 1개씩 자동으로 제출한다. (내려놓기 규칙과 같음) **[확정]**
- 제출한 음식은 배달원에게 날아가 쌓이고, 말풍선의 숫자가 채워진다. **[확정]**
- 지나가다 범위에 들어가도 자동으로 제출된다 (카운터로 가던 버거가 제출될 수 있음). 배달 지점은 카운터 동선에서 떨어진 곳에 둔다. **[확정]**
- 알바도 제출한다. 우선순위는 판매 다음·포장 위, **남은 시간 20초 이하면 급한 청소 다음**. **[확정]**

**결과**

- 배달원이 도착하면 "SPECIAL ORDER!" 알림을 띄운다. **[확정]**
- **성공:** 필요 수량을 모두 제출하면 즉시 성공. 보상(돈·경험치)을 **바로 입금**하고 "배달 성공" 알림, 배달원은 사람 출구로 퇴장한다. **[확정]**
- **실패:** 제한 시간이 0이 되면 실패. **보상 없음, 제출한 음식은 삭제된다.** "배달 실패" 알림, 배달원은 퇴장한다. **[확정]**

## 7. 오브젝트 정의 (기본 도형)

모든 오브젝트는 Unity Primitive와 단색 머티리얼로 만든다. 색상과 크기는 임시값이다. **[제안]**

### 7.1 캐릭터

| 오브젝트 | 도형 | 색 | 비고 |
| --- | --- | --- | --- |
| 플레이어 | Capsule | 파랑 | |
| 알바 | Capsule | 초록 | |
| 일반 손님 | Capsule | 노랑 | 주문 1~4개 |
| VIP 손님 | Capsule | 보라 (임시) | 주문 6~10개, 말풍선 색 다름 |
| 진상 손님 | Capsule | 빨강 | |
| 드라이브스루 차량 | Cube | 회색 | 줄 간격 3.0에 맞는 길이 |
| 배달원 | Capsule | 주황 | 머리 위 말풍선 (6.14) |

### 7.2 픽업 오브젝트 (Pickup Object) **[확정: 명칭]**

플레이어·알바가 집을 수 있는 오브젝트를 **픽업 오브젝트**라 부른다. 코드에서는 `PickupObject` 컴포넌트로 표현한다. (돈 오브젝트는 들고 다니는 대상이 아니므로 픽업 오브젝트가 아니다. 7.4 참고)

| 분류 | 종류 | 도형 | 색 |
| --- | --- | --- | --- |
| 음식 | 버거 | 납작한 Cylinder | 갈색 |
| 음식 | 커피 | 작은 Cylinder | 진갈색 |
| 음식 | 포장 버거 | 작은 Cube (종이봉투) | 황토색 |
| 쓰레기 | 쓰레기 | 작은 Cube | 회색 |

- 모두 풀링 대상이다.
- 한 번에 들 수 있는 개수는 **최대적재량**(스탯) N으로 제한한다. 음식과 쓰레기는 같은 적재량을 공유한다.
- **음식과 쓰레기는 동시에 들 수 없다.** `CarryStack`은 현재 적재 종류(None / Food / Trash)를 갖고, 종류가 다른 오브젝트는 줍지 않는다. **[확정]**
- 음식끼리는 종류(버거·커피·포장 버거)가 섞여도 된다. 내려놓을 때는 받는 곳이 받는 종류만 골라 내려놓는다. (6.3) **[기본값]**
- 줍기·내려놓기 규칙은 6.3을 따른다. (0.1초에 1개, 머리 위 스택)
- 스택은 캐릭터 머리 위에 위로 쌓이는 방식이다. 쌓일 때 `DOJump`로 이동한다.

## 8. 재화, 스탯, 업그레이드

### 8.1 재화

| 재화 | 획득 | 사용 |
| --- | --- | --- |
| 돈 | 음식 판매, 식사 후 팁, 진상 손님 해결 보상, 드라이브스루 판매 (돈 더미에서 플레이어가 수거), 배달 성공 보상 (즉시 입금) | 해금, 업그레이드, 알바 고용 |
| 경험치 | 판매, 진상 손님 처리, 드라이브스루 판매, 배달 성공 | 레벨업 (2장 7번 참고) |

- **시작 돈은 100**이다. **[확정]**
- 쓰레기 청소에는 돈·경험치 보상이 없다. (6.10)
- 레벨업 시 일부 업그레이드 항목과 구역 해금이 열린다. **[기본값]**
- 경험치 → 레벨 테이블은 ScriptableObject(`LevelTable`)로 정의한다. Lv N → N+1 필요 경험치 = round(50 × 1.5^(N-1)), 최대 Lv 20. **[기본값]**
- **레벨 0으로 시작한다.** 매장(Zone 0)을 해금하면 Lv 1이 된다 (경험치가 아니라 해금 보상, `UnlockDefinition`의 Grant Level). 그 뒤부터 경험치로 오른다. **[확정]** (2026-10-13)
- 해금 박스의 필요 레벨 표시는 숫자만 쓴다 (예: "1"). **[확정]**
- 레벨업 시 "LEVEL UP! Lv N" 팝업과 HUD 레벨 숫자 튐 연출만 있고 보상은 없다. 새로 열린 업그레이드·해금 박스는 자동으로 반영된다. **[확정]**

### 8.2 업그레이드 가능 목록

각 항목은 레벨별 `비용`과 `효과 수치`를 갖는다. 세부 스탯은 **[제안]**이며 확정 전까지 변경될 수 있다.

| 대상 | 업그레이드 스탯 | 상태 |
| --- | --- | --- |
| 플레이어 | 이동속도, 최대적재량, **수익 배율**(x1 ~ x10) | [확정] |
| 알바 | 이동속도, 최대적재량, 알바 인원수(최대 6명), **행동 속도**(판매·포장 속도 배율, 1배 → 최대 5배. 간격 = 기본 간격 ÷ 행동 속도) | [확정] (2026-10-13 판매 간격 → 행동 속도) |
| 버거 기계 | 초당 생산량, 최대 생산량(재고 상한) | [확정] |
| 기계 (커피 등) | 버거 기계와 동일 구조 | [제안] |
| 카운터 (기본, 드라이브스루) | 없음 (재고 무제한) | [확정] |
| 손님 테이블 | 버거 1개 먹는 시간 단축. **모든 테이블 공통** 적용 | [확정] |
| ~~알바~~ | ~~포장 간격~~ → 행동 속도에 포함 | [확정] |
| 포장 테이블 | 투입 칸·출력 칸 상한 | [제안] |

- **수익 배율:** 돈 더미에 쌓이는 모든 수익(판매·팁·드라이브스루·진상 보상)과 배달 즉시 입금 금액에 배율을 곱해 **반올림**한다 (0.5는 올림, 예: 팁 3 × 1.5 = 4.5 → 5). 최소 x1, 최대 x10. 최대에 닿으면 더 살 수 없다. **[확정]**
- **쓰레기통은 업그레이드 대상이 아니다.** **[확정]**
- 알바 인원수의 시작값은 **0명**이고, 첫 업그레이드가 곧 첫 고용이다. **[기본값]**
- 플레이어의 판매 간격은 업그레이드하지 않는다. (0.1초 고정) **[확정]**

### 8.3 업그레이드 데이터 구조 **[제안]**

```
UpgradeDefinition (ScriptableObject)
- id
- target       (Player / Worker / Machine / Counter / Table)
- statKey      (MoveSpeed / MaxCarry / ProducePerSec / MaxStock / SellInterval / ...)
- requiredPlayerLevel
- levels[]     { cost, value }

UnlockDefinition (ScriptableObject)
- id, target(해금되는 오브젝트), cost, requiredPlayerLevel
```

- 비용 곡선 기본식: `cost = round(baseCost × 1.35^level)` **[기본값]**
- 스탯 값 = GameConfig 기본값 + 업그레이드 레벨 × 레벨당 변화량. 줄여야 하는 스탯(먹는 시간)은 음수 변화량. **[확정: 구현 구조]**
- 효과 수치는 레벨당 선형 증가를 기본으로 한다. **[기본값]**
- 현재 레벨은 `ReactiveProperty<int>`로 보관하고, 스탯 값이 바뀌면 구독자(UI, 캐릭터)가 자동 반영한다.

## 9. 알바 AI

### 9.1 상태 (FSM)

```
Idle(대기) → Move(이동) → Work(작업) → Idle
```

| 상태 | 설명 |
| --- | --- |
| Idle | Task 큐를 확인하고, 수행할 Task가 있으면 예약 후 Move로 전환 |
| Move | Task 위치로 이동 (이동 방식은 아래 참고) |
| Work | Task 종류에 따라 작업 수행(픽업·내려놓기·판매·게이지 채우기). 완료하면 예약을 해제하고 Idle로 복귀 |

- 이동은 **NavMesh**(AI Navigation 패키지)로 스테이션을 피해 다닌다. 시작 시와 해금으로 시설이 나타날 때마다 NavMesh를 다시 굽는다. **[확정]**
- 고용한 알바는 **직원 대기 지점**에서 나타난다. 할 일이 없으면 **그 자리에서 대기**한다. **[확정]**
- 알바는 플레이어처럼 지나가며 자동으로 줍지 않고, 맡은 일의 대상에서만 줍고 내려놓는다. **[확정: 구현]**
- 알바 판매 진행도 게이지는 표시하지 않는다. **[확정]**
- 알바도 6.3의 픽업 규칙을 따른다. (0.1초에 1개, 음식과 쓰레기 동시 소지 불가)
- 알바는 돈을 수거하지 않는다. 돈 더미 수거는 플레이어 전용이다. (6.11)

### 9.2 Task 종류

플레이어와 알바는 모든 Task를 수행할 수 있다. 플레이어는 Task를 직접 수행하고, 알바만 TaskBoard에서 Task를 배정받는다. **[확정]**

| Task | 내용 | 상태 |
| --- | --- | --- |
| 운반 | 기계 출력 지점의 음식을 집어 카운터에 투입 | [확정] |
| 청소 | 테이블 위의 쓰레기를 집어 쓰레기통에 버림. 쓰레기가 쌓인 테이블이 대상. 강제 청소 상태의 테이블 우선 | [확정] |
| 판매 | 카운터 응대 위치에 서서 N초에 1개씩 줄 맨 앞 손님에게 판매 (6.7). 재고가 있고, 줄 맨 앞 손님이 좌석을 예약한 상태일 때 생성 | [확정] |
| 진상 손님 처리 | 진상 손님 근처로 이동해 게이지를 채워 해결 (6.8) | [확정] |
| 포장 운반 | 버거를 포장 테이블에 투입 (6.13) | [기본값] |
| 포장 | 포장 위치에 서서 포장 진행. 버거 4개 이상, 출력 칸 여유가 있을 때 생성 (6.13) | [기본값] |
| 드라이브스루 운반 | 포장 버거를 드라이브스루 카운터에 투입 (6.13) | [기본값] |
| 드라이브스루 판매 | 창구에 서서 맨 앞 차량에게 판매 (6.13) | [기본값] |
| 배달 제출 | 주문 품목을 들고 배달원에게 제출 (6.14) | [기본값] |
| 그 외 | 필요 시 추가 | [미정] |

- 드라이브스루·배달 관련 Task는 알바 단계(P9)가 끝난 뒤 각 기능 단계(P11, P12)에서 TaskBoard에 추가한다.

### 9.3 Task 배정과 플레이어의 가로채기

- 전역 `TaskBoard`가 Task를 등록하고, 알바는 Idle일 때 가장 우선순위가 높고 가까운 Task를 가져간다. **[기본값]**
- 한 Task는 한 명만 수행하도록 **예약(Reserve)** 한다. 중복 배정과 한 스테이션에 몰리는 문제를 막기 위함이다.
- **플레이어 가로채기 [확정]:** 알바가 Task를 수행하려는 중(Move·Work)에 플레이어가 먼저 그 일을 해버리면, 알바는 그 Task를 포기하고 예약을 해제한 뒤 **다음 Task를 가져간다.**
  - 알바는 Move·Work 중 매 프레임(또는 일정 주기)마다 Task가 아직 유효한지 검사한다.
  - 유효하지 않은 경우의 예: 응대 위치를 플레이어가 점유함, 음식이 이미 다른 사람에게 집힘, 쓰레기가 이미 치워짐, 진상 손님이 이미 해결됨.
  - 응대 위치에서는 플레이어가 우선한다. 알바가 판매 중에 플레이어가 들어오면 알바가 양보한다.
- **우선순위는 상황에 따라 바뀐다.** **[확정]** (진상·배달·드라이브스루·포장 Task는 각 단계에서 이 표에 끼워 넣는다)

| 순위 | 일 | 조건 |
| --- | --- | --- |
| 1 | 들고 있는 것 처리 | 음식 → 받는 곳, 쓰레기 → 쓰레기통 |
| 2 | 막힌 좌석 청소 | 맨 앞 손님이 좌석을 못 구해 판매가 막혔거나, 강제 청소 테이블 |
| 3 | 판매 | 맨 앞 손님이 좌석을 확보(가능)하고 재고가 있을 때만. 팔 일이 1.5초 없으면 다른 일로 |
| 4 | 운반 | 카운터 재고가 줄의 남은 주문량보다 모자랄 때만. 재고가 충분하면 운반하지 않고 대기 |
| 5 | 일반 청소 | 그 밖의 쓰레기 |

- 운반은 기계에 있는 만큼 바로 집어 출발한다 (적재량까지 기다리지 않음). **[확정]**
- 알바가 **음식을 들고 있으면** 운반(카운터 투입)만 수행하고, **쓰레기를 들고 있으면** 쓰레기통에 버리는 것을 먼저 끝낸다. 들고 있는 것을 처리한 뒤에 다른 종류의 Task를 받는다. **[기본값]** 가로채기로 Task를 포기한 경우에도 들고 있는 물건은 유지한 채 위 규칙을 따른다.
- 알바 인원수는 업그레이드(8.2)로 늘어난다. 판매 Task는 응대 위치가 1곳이므로 동시에 1명만 수행한다.

### 9.4 알바 역할(Role) **[확정]**

- **모든 알바가 모든 Task를 수행한다.** 역할을 나누지 않는다.

## 10. 맵 확장

- 매장 전체는 하나의 Area(6.12)이고, 그 안을 **구역(Zone) 단위로 순차 확장**한다. **[확정]**
- **Zone은 매장 공간(크기)을 넓히는 단위다.** Zone을 해금하면 바닥·벽이 넓어지고, 넓어진 공간 안의 시설은 각자의 해금 박스로 연다. **[확정]**
- **단계적으로 나타난다.** 이전 Zone의 시설이 모두 해금되면 → 다음 Zone의 **확장 박스**만 나타나고 → 확장하면 **새 바닥·벽이 솟아오르고 칸막이 벽이 내려가며 사라진 뒤** → 안쪽 시설 해금 박스가 나타난다. (`ZoneManager`) **[확정]**
- 플레이어와 알바는 **NavMesh 위에서만** 이동한다. 확장하면 NavMesh가 갱신되어 이동 범위가 넓어지고, 시설은 통과하지 않고 미끄러지듯 돌아간다. **[확정]**
- 해금은 6.4의 해금 박스 방식을 따른다. 필요 **플레이어 레벨**이 있으면 레벨 조건 + 돈 투입을 모두 만족해야 한다. **[기본값]**
- 해금 시 연출: 새 바닥·벽은 아래에서 솟아오르고, 사라지는 벽은 아래로 내려감. 시설 박스는 튀어나오듯 등장 **[확정]** (카메라는 플레이어를 따라가므로 범위 확장 없음)

| 구역 | 내용 | 해금 박스 (비용 / 필요 레벨은 임시) | 상태 |
| --- | --- | --- | --- |
| ZoneStart (시작) | 매장 밖 공간. 플레이어가 여기서 시작 | 없음. 처음부터 Zone 0 확장 박스(매장 입구)가 보임 | [확정] |
| Zone 0 | 매장 구매 | 매장 확장 40 → 카운터, 버거 기계, 테이블 3개(각 20). 쓰레기통은 매장과 함께 등장. **시설을 모두 해금하면 손님 입장 시작** | 내용 [확정] / 수치 [기본값] |
| Zone 1 | 업그레이드 공간 | 매장 확장 400 (Lv 2) → 플레이어 업그레이드 패드, 알바 업그레이드 패드 (각자 해금 박스) | 내용 [확정] / 수치 [기본값] |
| Zone 2 | 드라이브스루 | 매장 확장 (Lv 4) → 포장 테이블 150, 드라이브스루 카운터 200. **완료 시 차량 등장** | 내용 [확정] / 수치 [기본값] |
| Zone 3 | 배달 | 매장 확장 → 배달 지점 (해금 박스). **완료 시 배달원 등장** | 내용 [확정] / 수치 사용자 조정 |
| ZoneEnd | 데모 완료 | 확장 박스 해금 시 완료 알림 | [확정] |

- 2026-10-13: Zone 4 커피 매장은 제외한다. Zone 3 배달(6.14)은 한때 제외했다가 같은 날 다시 추가했다. **[확정]**
- 테이블마다 각자 팁 더미가 붙는다.
- 데모 종료: Zone 3 시설을 모두 해금하면 **ZoneEnd 확장 박스**가 나타나고, 해금하면 "데모 완료" 알림을 띄운다. **[확정]** (2026-10-13)
